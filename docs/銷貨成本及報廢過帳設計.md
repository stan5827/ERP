# 銷貨成本與報廢過帳設計

## 銷貨成本（COGS）

出貨單簽收時，系統依明細指定的 SKU、批號、倉庫與儲位計算實際批號成本，並在同一資料庫交易中：

1. 寫入銷貨出庫 `InventoryTransaction` 成本快照。
2. 扣減批號及 SKU 庫存。
3. 產生銷貨成本傳票：借記銷貨成本、貸記成品存貨。
4. 更新出貨單簽收狀態。

傳票以 `DeliveryOrder` 作為來源單據，避免同一出貨單重複產生傳票。批號成本或必要科目映射缺漏時，簽收及庫存過帳均應被阻止。

## 總帳科目映射

使用財務科目表中的有效科目 ID 設定映射，不在程式碼中寫死公司科目代碼。管理 API：

- `GET /api/erp/finance/accounting-mappings`：列出映射用途、要求的科目類型及目前設定。
- `PUT /api/erp/finance/accounting-mappings/{mappingKey}`：設定有效科目。

| 映射鍵 | 用途 | 要求科目類型 | 狀態 |
|---|---|---|---|
| `sales_cogs` | 銷貨成本借方 | Expense | 出貨過帳必要 |
| `finished_goods_inventory` | 成品存貨貸方 | Asset | 出貨過帳必要 |
| `scrap_loss` | 報廢損失借方 | Expense | 預留，待報廢流程實作 |
| `quarantine_inventory` | 隔離品存貨貸方 | Asset | 預留，待報廢流程實作 |
| `production_variance` | 已核准工單異常成本借方 | Expense | 異常分攤結算必要 |

新映射表需先套用 EF Core 遷移，並由財務設定映射後，COGS 傳票才可過帳。此功能不指定預設科目代碼。

## FQC 隔離品報廢核定

FQC 隔離成品報廢單保存原因分類、說明、數量、成本快照、申請人及簽核事件，依序由品保判定、財務核定。退回案件由原申請人補正後重新送審，簽核軌跡保留。狀態依序為 `pending_quality_review`、`pending_finance_review`、`approved_pending_disposal`；退回狀態為 `returned_to_requester`。

財務核定只代表報廢申請獲准，不代表完成實體清運、庫存扣帳或會計入帳。核定後隔離庫存仍維持鎖定；系統不會自動扣減隔離庫或 SKU 庫存，也不會產生傳票。待公司核定會計政策與作業權責後，才另行設計實體處理及過帳流程，並設定 `scrap_loss`、`quarantine_inventory` 科目映射。

## 返修完成後複檢與結案

返修工單最後工序報工完成後轉為 `pending_fqc`，阻止工單提前完工或繼續報工。送檢時沿用來源成品批號，並建立唯一的來源 FQC 批次關聯；來源隔離品須全數領用，複檢數量不得超過領用數量。返修複檢只接受合格或不合格判定，不允許特採或再次返修。

返修工單須在複檢判定完成、合格數全數入庫，且不合格數已有財務核定的報廢單後才能結案。未完成的隔離量仍維持鎖定。結案檢查不會自動扣除隔離庫存、移轉至報廢暫存區或建立會計傳票；這些實體處理與會計政策仍需另行核定。

## 月結成本呈現

已過帳的報廢成本應與可資本化製造成本分開呈現，不得再計入可銷售成品單位成本。月結報表應分列：

- 完工入庫與銷貨批號實際成本。
- 已過帳報廢損失。
- 待會計核定報廢金額（僅供追蹤，不入帳）。
- 工單實際成本與標準成本差異。

未過帳報廢不得提前扣除庫存或列入已認列損失；已過帳報廢則不得在工單可資本化成本與報廢損失中重複計價。

## 工單實際成本結算

工單完成 FQC 放行及完工入庫後，可透過 `POST /api/v1/erp/workorders/{id}/costing/settle` 結算。既有 `/api/erp/...` 路徑仍保留相容性。結算只接受已完工、具有實際成本、FQC 已放行且放行數全數入庫的工單；有待簽核差異分攤或待處置隔離品時會拒絕結算。

工程變更或產線異常成本必須明確連結一筆工單實際成本來源，不會僅依報工異常旗標推估金額。來源類型為 `material`、`labor`、`machine` 或 `overhead`，並以實際成本記錄 ID 與金額建立分攤：

- `POST /api/v1/erp/workorders/{id}/costing/variance-allocations`：建立待簽核分攤；原因代碼為 `engineering_change` 或 `production_anomaly`。同一工單應先建立全部分攤，再開始簽核；已有分攤核准後不接受追加。
- `GET /api/v1/erp/workorders/{id}/costing/variance-allocations`：查詢分攤與簽核軌跡。
- `POST /api/v1/erp/workorders/{id}/costing/variance-allocations/{allocationId}/approvals`：簽核分攤。建立者不得簽核；依該工單全部有效差異分攤的合計金額判定門檻，小額沿用部門主管簽核，大額沿用 CFO 與總經理雙簽，門檻及角色取自 `AccountingPolicy`，避免拆分分攤繞過簽核門檻。

來源分攤總額不得超過該筆實際成本。結算時，正常可資本化實際成本為「工單實際成本－已核准異常分攤」；傳票調節既有完工入庫成品金額，並結清 WIP。異常分攤逐筆借記 `production_variance`，分錄摘要包含分攤 ID、成本來源及原因代碼，以便由總帳追溯分攤紀錄；異常成本不再資本化至成品。工單快照仍保存完整實際成本及實際－標準成本差異，並另外保存異常成本與可資本化實際成本。

結算以資料庫交易及工單列鎖避免重複過帳；傳票金額調節以先前已過帳的完工入庫金額為基礎，必要的成品、WIP、差異科目映射缺漏或會計期間已關帳時會阻止結算。新增差異分攤資料表及成本快照欄位的 Migration 尚未套用，部署前須先審核並套用 Migration，且由財務設定 `production_variance` 映射。
