#### 具體問題

1. 正式 Keycloak realm 尚未建立，正式 Realm 名稱、public client、redirect URI、MFA policy、session lifetime、封鎖及恢復流程仍需核准。
2. 正式郵件送達、邀請有效期、寄件重試、退信、MFA 註冊及供應商帳號停權流程尚未驗收。
3. DMZ／APISIX、WAF、TLS 憑證、DNS、來源限制、速率限制及內部管理介面隔離尚未完成正式部署。
4. MinIO 私有物件儲存、ClamAV 掃描、掃描逾時、檔案加密、保留期限及刪除流程尚未完成正式驗收。
5. Supplier Portal 已有 RFQ、PO 與請款前端切片，但 ASN 頁面尚未出現在獨立 Portal 路由，RFQ／PO 完整操作與正式供應商 UAT 尚待閉環。

### 二、供應商請款 Portal

#### 具體問題

1. 財務尚未核定發票格式、發票號碼唯一規則、幣別、稅額、未稅／含稅精度、匯率來源、日曆及發票日期限制。
2. 採購／財務尚未核定 PO、收貨、驗收、退貨、已請款餘量、單一／多來源及部分請款規則。
3. 三方核對容差、例外核准、價格／數量差異、稅額差異、幣別差異及責任角色尚未成正式政策。
4. 重複發票、併發送審、版本衝突、建立草稿冪等及核准重試可能造成重複 AP；需以資料庫唯一約束與交易鎖定驗證。
5. 正式 MinIO／ClamAV、附件下載權限、掃描中／clean／rejected 狀態及掃描 SLA 尚未驗收。
6. 輸入與核准後資料需保留修訂快照、審核原因、操作者、附件雜湊及來源單據。退回補件與多次重送需可逐版本追查。
7. 目前前後端切片不代表正式 UAT；財務審核介面、退回、拒絕、取消、補件、核准及正式 AP 建立仍需完整隔離環境驗收。

### 三、AI ERP 整合

#### 具體問題

1. `POST /api/erp/llm/complete` 目前固定回傳 503，僅另有受政策保護的底層 LLM service；這代表模型尚未具備正式入口與灰度流程。
2. 已有 feature egress policy，但 provider、model、endpoint、資料分類、責任人及 model contract 尚未經正式核准。
3. 目前缺少可在正式環境驗證的集中式 kill switch、啟用時間、停用者、理由及停用後立即阻斷。
4. 缺少 API 層使用者白名單、部門／成本中心／工作中心 scope 與撤權立即生效驗收。
5. 目前完整定義「可送模型資料」與遮罩規則仍不足；跨部門資料、敏感欄位及去識別化欄位需資料 owner 核准。
6. 實際回答尚需 facts／數字／單位核對、拒絕回答、提示詞改寫、模型幻覺及稽核重現測試。
7. 寫入工具 allowlist 必須維持空集合；工單、採購、庫存、發料、完工及核准不得由 AI 執行。

#### 建議工作包

| 順序 | 工作項目 | 負責角色 | 完成證據 |
|---|---|---|---|
| A1 | 核定 provider、model、endpoint、contract、資料分類、保留、責任人及資料 owner。 | 資安、架構、業務 | 變更核准紀錄與 secrets inventory。 |
| A2 | 實作後端集中式 `enabled` kill switch，支援配置／管理 API／restart 全面停用。 | AI 平台、營運 | 停用後 API 立即回 503、稽核有操作者與原因。 |
| A3 | 實作 seed-user／部門 scope、撤權版本與 JWT revision 即時失效。 | IAM、後端 | 換身分、撤權及跨部門拒絕測試。 |
| A4 | 補資料欄位白名單、遮罩、去識別化、fact ID、單位及數字一致性。 | 資料 owner、後端 | 敏感欄位不外流、回答可追溯 facts。 |
| A5 | 禁止 shell、DB、瀏覽器、任意 HTTP、MCP 與 ERP 寫入工具；維持唯讀。 | 資安、平台 | tool policy 失敗與 allowlist 稽核。 |
| A6 | 隔離灰度、kill switch rollback、幻覺、拒絕回答及稽核重現驗收。 | 資安、業務、營運 | 正式灰度與回退演練簽認。 |

**啟用門檻：** provider／model／endpoint／資料分類已核准，kill switch 可從營運介面立即停用，撤權與跨部門隔離通過，唯讀工具 allowlist 完整，正式灰度負責人已指定。

## 結論摘要

建議依序處理：

1. 保全並盤點現有未提交變更，建立可靠的基線。
2. 優先處理後端執行環境支援週期與容器升級。
3. 完成員工 ESS 的打卡、請假申請／審核／假額及薪資資料驗收。
4. 建立可在乾淨環境重複執行的全套測試與 CI 品質門檻。
5. 重新驗收正式環境的權限、網路、秘密、稽核及背景工作。
6. 再依業務優先度推進供應商入口、AI 整合及供應商請款 Portal。
