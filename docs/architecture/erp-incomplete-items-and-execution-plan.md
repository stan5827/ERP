# ERP 未完成項目盤點與建議順序

**盤點日期：** 2026-11-04
**盤點依據：** 目前工作目錄、既有架構規劃文件、近期員工 App 實際操作與已執行的定向測試。
**範圍說明：** 本文件是執行規劃，不是完整安全稽核，也沒有重跑全套測試或驗證正式環境。工作目錄包含大量未提交及未追蹤變更；應先釐清變更來源，不可直接覆蓋或清理。

## 結論摘要

建議依序處理：

1. 保全並盤點現有未提交變更，建立可靠的基線。
2. 優先處理後端執行環境支援週期與容器升級。
3. 完成員工 ESS 的打卡、請假申請／審核／假額及薪資資料驗收。
4. 建立可在乾淨環境重複執行的全套測試與 CI 品質門檻。
5. 重新驗收正式環境的權限、網路、秘密、稽核及背景工作。
6. 再依業務優先度推進供應商入口、AI 整合及供應商請款 Portal。

## 分階段執行方案

### 階段 0：保全變更與建立可靠基線

1. 保存目前工作目錄狀態，確認未提交變更的來源及負責人。
2. 將修改和未追蹤檔案分類為已完成、進行中、待驗證或歷史產物。
3. 確認敏感設定、資料及測試資料未被納入版本控制。
4. 在不覆蓋既有工作前提下，重新建立後端、Web、員工 App 的 build/test 基線。

**階段完成門檻：** 變更來源清楚，工作目錄有可審查的分批方式，並有記錄完整的測試基線。

### 階段 1：支援週期與正式環境安全

1. 確認目前工作目錄中的 .NET 10、Node 24、EF Core、Npgsql、SDK 與容器基底映像版本及官方支援週期。
2. 驗證尚未提交的後端／前端容器與 CI 升級變更；完成資料庫 Migration、測試與回退演練。
3. 更新 CI，確保容器建置、後端測試、前端建置及必要掃描都在 PR 執行。
4. 重新驗收 API 權限、員工與組織資料範圍、部署秘密及管理服務網路界線。

**階段完成門檻：** 使用中的執行環境仍受支援，乾淨 CI 建置與測試通過，正式環境安全閘門有明確核准紀錄。

### 階段 2：完成員工 ESS 業務閉環

1. 核定公司打卡圍欄、時段、時區及遲到規則，完成現場打卡測試。
2. 先建置 ERP 班表／假日日曆；之後核定請假時數與假額政策，完成申請、審核、退回、取消及假額流程測試。在該流程完成前，申請與核准端點維持 503 fail-closed。
3. 由 HR 決定已建立的 `TEST` 請假申請如何處理。
4. 由薪資管理者確認測試員工資料是否應有已發布薪資單，驗證 App 資料隔離與顯示。

**階段完成門檻：** 由業務負責人確認流程、權限及資料結果；未核定或未驗收的實際出勤、薪資與假額不以開發測試代替。

### 階段 3：全系統回歸與營運驗收

1. 在乾淨環境重跑後端單元測試、PostgreSQL 整合測試、Web／App build 和端到端流程。
2. 修正失敗並記錄已知 skip；確認資料庫 Migration 可在目標環境套用及回復。
3. 驗證稽核記錄、背景工作、健康檢查、告警、日誌遮罩及部署回退程序。
4. 針對核心跨模組流程建立可追蹤的資料一致性與權限驗收案例。

**階段完成門檻：** PR 品質門檻與部署 smoke test 穩定可重複執行；重大失敗與例外均有負責人及期限。

### 階段 4：依業務優先度推進其他入口

1. 供應商入口：先完成正式身分、MFA、網路隔離、TLS 及附件服務安全驗收，再完成 ASN 前端。
2. AI 整合：維持預設關閉，完成模型出口、資料 owner、資料隔離與回退政策後，以合成資料進行 PoC。
3. 請款 Portal：先完成財務／採購政策及 API 決策，再實作草稿、附件、送審及審核閉環。

**階段完成門檻：** 各入口分別經業務、安全及營運負責人簽核；未完成門檻的功能維持關閉或不對外公開。
