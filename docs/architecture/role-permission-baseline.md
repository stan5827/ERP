# 全系統角色與權限基準

## 權限原則

- `RolePermissionCatalog` 是系統預設角色及角色權限的唯一來源；`PermissionCatalog` 維護模組、動作及繁體中文權限說明。
- 初始化只套用一次。完成後由系統管理員在「系統設定 → 權限管理」調整的結果，不會因服務重新啟動而被重設。
- 新增角色不會自動指派給任何帳號；既有使用者與角色指派會保留。
- 預設不授予一般角色刪除權，也不以整個模組權限代替個別動作授權。採購沖銷只授予採購主管。
- 系統管理員 `Admin` 維持後端全域特權，不透過一般角色權限清單授權，應限制帳號數量並保護登入憑證。
- 權限變更會更新受影響使用者的安全版本，使舊登入權杖失效；使用者須重新登入。
- 角色權限是控制器／模組層級，不能取代資料列、部門或倉庫範圍控管。指派前仍須確認使用者所屬範圍。

## 預設角色

| 角色代碼 | 顯示名稱 | 權責摘要 |
|---|---|---|
| `Admin` | 系統管理員 | 帳號、角色、權限與跨模組維運；全域最高權限 |
| `HR Manager` | 人資主管 | 人事、組織、出勤、請假及薪資政策送審 |
| `Production Supervisor` | 生產主管 | 工單、產線執行及報工審核；遵守不同人覆核 |
| `Operator` | 現場作業員 | 工單檢視與本人／班組報工 |
| `Finance` | 財務人員 | 財務日常資料及成本、預算、成本中心查詢 |
| `Finance Manager` | 財務主管 | 會計、預算、成本結轉與成本中心覆核 |
| `Sales Manager` | 業務主管 | 客戶、報價、訂單、出貨及業務核准 |
| `Sales Representative` | 業務人員 | 客戶往來、報價及訂單日常維護 |
| `Purchasing Manager` | 採購主管 | 採購、供應商協作、採購核准及必要沖銷 |
| `Purchasing Specialist` | 採購專員 | 請購、採購及供應商日常維護 |
| `Warehouse Manager` | 倉儲主管 | 庫存、條碼、倉儲作業及必要覆核；可唯讀查詢工藝與產品主檔以執行工藝檢驗 |
| `Warehouse Operator` | 倉管人員 | 庫存收發、調撥、盤點及條碼作業；可唯讀查詢工藝與產品主檔以執行工藝檢驗 |
| `Quality Manager` | 品質主管 | 品質檢驗、品質異常及品質判定覆核 |
| `Quality Inspector` | 品檢人員 | 進料、製程與成品檢驗 |
| `Production Planner` | 生管與物料規劃人員 | MPS、產能、MRP 與 APS 排程 |
| `Engineering Manager` | 工程主管 | 工藝、BOM、工作中心、量測主檔及工程變更覆核 |
| `Engineering Engineer` | 工程人員 | 工藝、BOM、工作中心及研發資料維護 |
| `Maintenance Technician` | 設備維護人員 | 設備維修、保養及資產查詢 |
| `Asset Manager` | 資產管理人員 | 資產資料、折舊與處置流程 |
| `R&D Engineer` | 研發人員 | 研發專案資料與核准後的研發流程 |
| `ESG Specialist` | 永續管理人員 | 碳盤查與 ESG 資料及報告 |
| `AI Analyst` | AI 分析人員 | AI 監控與決策查詢，不含代理流程編輯 |
| `Employee` | 一般員工 | 系統總覽與行事曆；個人自助服務另依員工身分控管 |

供應商入口採獨立的供應商入口驗證與政策，不以內部 ERP 角色取代。隔離 UAT 的合成倉儲角色僅供測試，保留其既有權限指派，不應用於正式帳號。

生產主管如需從銷售訂單轉發工單，僅授予 `sales:workordertransfer:page` 與 `sales:workordertransfer:execute`：可檢視符合條件的訂單佇列並執行轉發，不授予一般銷售模組或其他銷售資料的存取權。

## 部署與指派

1. 後端啟動時先建立權限目錄，再執行一次性角色基準初始化。
2. 初始套用會更新核心非管理員角色的預設權限；已指派角色的使用者會保留角色關聯，但舊權杖會失效。
3. 由系統管理員登入權限管理頁面，確認角色及權限後，再由「使用者管理」逐一指派角色。
4. 新角色預設無使用者指派。正式環境套用前，應先在 UAT 驗證角色權限及業務資料範圍。
