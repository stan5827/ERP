# Token 撤銷與授權效能決策 — Phase 0 草案

## 狀態

已記錄撤銷策略決定，並完成隔離本機 PostgreSQL 的成功登入／有效授權請求量測；正式環境基線與延遲預算仍待系統負責人核定。不得將尚未驗證的 production migration 或環境結果視為上線核准。

## 現況證據

- JWT 目前有效期取自 `Jwt:ExpireMinutes`，未設定時預設 480 分鐘。
- Token 含使用者識別、名稱、角色、權限及 `security_version` claims；受保護 JWT 請求會查詢 PostgreSQL 中的帳號、員工狀態、安全版本及目前有效角色綁定，任一狀態不符或查詢失敗均拒絕授權。
- `Program.cs` 註冊記憶體快取；未找到 Redis client 套件／服務註冊。僅有 Redis optional 註解不足以證明部署或跨節點一致性。
- 本機隔離 PostgreSQL 測量採單一合成 Admin 帳號及 TestServer；其成功登入與受保護 API 數據見下節，不能推導正式環境效能或負載能力。

## 已核定技術決定

| 項目 | 決定 | 狀態 |
|---|---|---|
| 撤銷權威來源 | 每次受保護 JWT 請求查 PostgreSQL 使用者帳號狀態及 security version；不依賴 Redis 或程序內快取 | 使用者已選擇 |
| 權威資料不可用 | 驗證失敗時拒絕授權，不得放行 | 使用者已選擇 |
| 效能門檻 | 先量測成功登入及有效受保護 API 延遲，再核定預算；不預設 P95 數字 | 使用者已選擇 |
| 員工狀態映射 | `active` 正常使用；`leave` 僅可讀本人 ESS；`terminated`／`inactive` 全面拒絕；復職不自動啟用帳號 | 使用者已核定實作政策；正式 HR 簽核仍需留存 |
| 五類核心角色 | Admin 全系統覆蓋；HR Manager、Production Supervisor、Operator、Finance 僅限核定模組；其餘舊角色停用、不自動映射；未指派新角色者 Default-Deny | 使用者已核定實作基準；正式部門簽核仍需留存 |
| 商務 API 預設存取 | 原核定為 Default／Fallback Policy 要求 Admin；2026-10-26 依後續 RBAC 功能需求更新為 authenticated + 全域 module/action 權限檢查，未授權一律拒絕；Admin 保留全域 bypass，管理端點仍保留 Admin 限制 | 原決定由後續功能需求取代；未授權仍 Default-Deny |

## 員工狀態與 ESS 實作決定

- 每次 JWT 驗證會讀取帳號啟用狀態、安全版本、綁定員工及員工狀態；沒有有效員工綁定、版本不符或資料庫查詢失敗時拒絕請求。
- `active` 可正常進入需登入的 API。`leave` 可登入，但每次請求僅允許 `GET /api/erp/ess/*`。ESS 查詢使用簽章 Token 內的 EmployeeId，API 不接受呼叫端指定員工。
- ESS 目前提供本人薪資摘要、出勤及請假紀錄唯讀 API；薪資回應不包含銀行帳號、成本分攤或備註。
- `terminated`／`inactive` 及未知員工狀態均拒絕登入與 JWT API。離職／停用會在同次 `SaveChanges` 停用綁定帳號、遞增 `SecurityVersion` 並記錄操作者、前後狀態與原因；`leave` 保留帳號啟用以供本人 ESS 使用，但同樣遞增版本。
- 復職遞增安全版本並清除離職欄位，但不重新啟用已停用的 User，也不恢復角色。部門、職稱或職等異動需提供原因、記錄異動並撤銷既有 Token；不自動變更或推定角色。
- 新帳號僅可綁定 `active` 員工，且員工必須具備一種身分證明（國民身分證、護照或居留證號）、到職日、有效部門及有效職稱；開通後首次登入必須先變更密碼。
- 明確匿名路由為登入、舊註冊拒絕回應、根目錄服務狀態及 `/health`、`/health/ready`。MVC API 預設要求登入並由全域權限篩選器依控制器模組及 HTTP 動作檢查資料庫授權；未映射控制器或未授權動作一律拒絕。角色管理、帳號管理、權限樹維護及管理員密碼重設仍限 Admin。

## 實作範圍與上線注意

- 本階段實作帳號 `IsActive` 與 `SecurityVersion` 的每請求驗證；密碼變更／重設、帳號停用、角色／權限變更會遞增版本。
- 密碼變更會使目前及其他既有 JWT 一併失效；前端清除目前憑證並提示使用新密碼重新登入。
- 狀態政策與本人 ESS 已按使用者核定範圍實作；尚未實作未來生效日排程、調職角色自動重算、限時緊急例外及 ESS 前端畫面。模組／動作級 RBAC 已套用至控制器 API；尚未實作資料列／欄位級範圍與 SoD。
- 新的每請求查詢同時驗證 Employee 關聯及狀態；原先只量測 User 狀態的本機延遲數據不代表此版本效能，部署前須重新量測並核定正式預算。
- 全域 Default／Fallback Policy 要求有效登入；全域權限篩選器對映射的控制器檢查 `module:action` 權限，未映射控制器拒絕存取。Admin 為全域最高權限；系統設定、使用者／角色管理及密碼重設等管理端點仍要求 Admin。變更角色權限會提高該角色使用者的 `SecurityVersion`，使既有 Token 失效。
- 既有未綁定員工帳號會被拒絕登入；先前唯讀預檢發現的未綁定帳號須先由 HR／系統管理者核准修復。不得直接在正式資料庫自動綁定或停用。
- 離職 API 僅接受不晚於當日的有效日期並立即停用；留停／調職的未來生效日排程尚未提供，不能宣稱已支援提前登錄與自動切換。
- 新版 JWT 必須包含 `security_version`。升級時既有未帶版本 claim 的 token 會被拒絕，使用者需重新登入。
- 新增 migration 尚未套用至任何正式或共用資料庫；部署前須先備份、審核 migration 順序及執行回滾演練。

## 效能實測紀錄

2026-10-24 以本機 Docker PostgreSQL 的隔離測試 schema 執行 ASP.NET Core integration host；成功登入 12 筆（排除 3 筆暖機），有效 JWT 的 `GET /api/erp/users` 40 筆（排除 5 筆暖機）：

| 操作 | P50 | P95 | 樣本數 |
|---|---:|---:|---:|
| 成功登入 | 244.12 ms | 306.05 ms | 12 |
| 有效 JWT `GET /api/erp/users` | 46.24 ms | 60.66 ms | 40 |

此為本機容器／測試主機的單一合成帳號量測，涵蓋目前每請求 PostgreSQL 帳號驗證；不是正式環境基線、負載測試或前後差異比較，因此不可作為 production SLA 或上線效能核准。

## 原暫定建議（未核定事項保留）

1. 以資料庫中的帳號安全版本／security stamp 與帳號、員工狀態作為權威來源；登入時將版本寫入 JWT。
2. 帳號停用、密碼重設、員工狀態轉換、角色指派或權限變更時，更新權威版本，使舊 Token 在下一次受保護請求立即失效。
3. 若要使用 Redis 作共享快取，須先確認正式部署、叢集共享、失效傳播、TTL 與資料庫回查行為。未驗證前不得依賴 Redis；單機 memory cache 不符合跨節點立即撤權要求。
4. 若權威版本／狀態不可查，受保護請求應 fail closed；登入與授權服務不可用時，回應明確且可觀測。
5. 先以代表性成功登入及有效 Token API 測量額外延遲，再由系統／資安核定效能預算與上線門檻；未核定 SLA 前不設定推測數字。
