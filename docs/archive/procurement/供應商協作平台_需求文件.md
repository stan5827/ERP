# 供應商入口網站 (Supplier Portal) 需求與規劃清單

供應商入口網站是企業架設的一個外部網頁系統，使供應商能透過專屬帳號登入，進行報價、訂單確認、交貨管理與帳務查詢，徹底將「尋源、訂單、帳務」等流程數位化，達成供應鏈協同作業 (Supply Chain Collaboration)。

以下為基於本次要求梳理出的八大模組功能清單 (Checklist)，可作為日後開發及驗收的基準。

---

## 1. 供應商帳號與主檔管理 (Supplier Account & Master Data)
- [ ] **線上註冊與資格審核**：提供供應商自助填寫公司基本資料，包含 KYC、合約條款勾選。
- [ ] **公司主檔維護**：供應商可自行更新公司基本資料、聯絡人、銀行匯款帳號、稅籍等。
- [ ] **證照與認證上傳**：提供 ISO 證書、保險證明等掃描檔上傳功能。
- [ ] **文件到期提醒**：系統自動偵測各類證照效期，並發送更新通知給供應商。

## 2. 採購與訂單協作 (Procurement & Order Collaboration)
- [ ] **採購邀請與投標／報價 (RFQ/RFP)**：
  - 檢視企業發佈的詢價單與規格附件。
  - 線上回報單價、交期與最小訂購量 (MOQ) 或上傳報價單附件。
- [ ] **採購訂單 (PO) 查詢與回覆**：
  - 接收最新 PO 通知。
  - 線上點選「確認接單」或「拒絕/請求修改」(例如數量或交期無法配合)。
- [ ] **交期與出貨資訊維護**：
  - 供應商回報交貨排程、回覆異常交貨原因。

## 3. 出貨、收貨與物流 (Shipping & Logistics)
- [ ] **出貨通知與包裝單建立**：
  - 供應商出貨前，線上產生包裝單/出貨單 (ASN, Advanced Shipping Notice)。
  - 列印標籤 (箱號、棧板資訊)，方便抵達企業倉庫時直接掃碼。
- [ ] **批號與效期追蹤**：輸入實際出貨的物料批號 (Lot Number)、製造日期與有效期限。
- [ ] **收貨狀態查詢**：供應商可檢視貨物抵達後的狀態（已收庫、部分短少、因品質不良遭退回等）。

## 4. 發票與付款 (Invoicing & Payment)
- [ ] **電子發票與請款單**：
  - 供應商線上開立請款單，並強制關聯對應的 PO 或收貨單 (GR)，達成防弊與快速勾稽。
- [ ] **發票審核狀態查詢**：追蹤請款單目前狀態 (待審、退回、已核准待付款)。
- [ ] **付款狀態與帳齡查詢**：
  - 查看預計付款日、歷次實際付款紀錄與銀行匯款水單資訊。

## 5. 文件與合約管理 (Document & Contract Management)
- [ ] **合約與規範文件下載**：
  - 提供企業採購條款、包裝規範、品質要求、ESG 稽核標準等文件的中央下載區。
- [ ] **合約版本更新與簽署**：
  - 供應商可上傳簽署完成的合約或進行電子簽章確認。
- [ ] **中央化文件庫**：雙方共享保密協議 (NDA)、材質測試報告 (SGS/RoHS) 的集中儲存空間。

## 6. 供應商績效與稽核 (Performance & Audit)
- [ ] **供應商績效看板 (Supplier Scorecard)**：
  - 供應商可自行觀看企業對其的評分記錄 (KPI，如交期準確率、品質合格率、價格競爭力)。
- [ ] **稽核與自評問卷**：
  - 提供定期的供應商自評表、ESG/CSR 調查問卷與地緣風險調查填寫介面。
- [ ] **不良改善追蹤 (CAPA/8D)**：
  - 當交貨品質異常時，線上回覆 8D 報告、糾正與預防措施 (CAPA)，直到企業結案。

## 7. 溝通與通知 (Communication & Notifications)
- [ ] **訊息中心／內嵌留言**：
  - 針對特定 PO 或發票建立討論串，雙方可留言互傳附件 (免除 Email 漏信問題)。
- [ ] **系統主動通知**：
  - 發生新 PO、發票被退回、文件即將到期時，透過 Email 與 Portal 推播通知。
- [ ] **公共公告欄**：
  - 企業發佈停機公告、政策更新或年度評鑑規則。

## 8. 權限、安全與使用者體驗 (Security & UX)
- [ ] **角色與權限控管**：
  - 供應商可設立管理者，並授權給底下業務窗口 (僅看報價)、財務窗口 (僅看發票請款)。
- [ ] **多語系與多時區支援**：介面支援英文及在地語言，便利國際化供應鏈。
- [ ] **行動裝置友善 (RWD) 與稽核軌跡 (Log)**：支援手機查收 PO，並留存所有敏感操作紀錄以備稽核。

---
### 下一步建議規劃
1. **資料庫擴充 (Prisma Schema)**：為現有 ERP 增加 `SupplierUser`, `PortalMessage`, `SupplierDocument` 等模型。
2. **前後端分離/獨立路由**：由於供應商是外部人員，建議在現有 React 系統中切出一道 `/supplier-portal` 獨立登入頁，並實作嚴格的 JWT 角色隔離；或者另外架設一套 Vite 專案。
