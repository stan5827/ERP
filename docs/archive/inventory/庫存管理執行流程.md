## 三、核心庫存異動流程

### 3.1 異動類型與觸發點

| 異動類型 | 觸發來源 | API 端點 | 庫存變化 | 批號處理 |
|---------|---------|---------|---------|---------|
| **領料出庫** | 領料單 | `POST /issues/:id/issue` | `qty - n` | 扣減批號 |
| **退料入庫** | 退料單 | `POST /returns/:id/return` | `qty + n` | 建立/累加 |
| **補料入庫** | 補料單 | `POST /supplements/:id/issue` | `qty + n` | 建立/累加 |
| **委外發料** | 委外單 | `POST /subcontracts/:id/issue` | `qty - n` | 扣減批號 |
| **委外收貨** | 委外單 | `POST /subcontracts/:id/receive` | `qty + n` | 建立批號 |
| **調撥出庫** | 調撥單 | `POST /transfers/:id/pick` | `qty - n` | 扣減來源 |
| **調撥入庫** | 調撥單 | `POST /transfers/:id/receive` | `qty + n` | 建立目標 |
| **完工入庫** | 完工單 | `POST /completions/:id/receive` | `qty + n` | 建立批號 |
| **銷貨出庫** | 出貨單 | `POST /sales/deliveries` | `qty - n` | 扣減批號 |

### 3.2 庫存異動核心邏輯

```typescript
// 所有庫存異動都遵循此模式
await prisma.$transaction(async (tx) => {
    // 1. 取得 SKU 當前庫存
    const sku = await tx.sku.findUnique({ where: { id: skuId } });
    const qtyBefore = sku.qty;
    const qtyAfter = qtyBefore + qtyChange;  // 正=加帳, 負=扣帳
    
    // 2. 建立異動紀錄
    await tx.inventoryTransaction.create({
        data: {
            trxId, skuId, type, qtyChange, 
            qtyBefore, qtyAfter, lotNumber, 
            relatedDoc, handler
        }
    });
    
    // 3. 更新 SKU 庫存
    await tx.sku.update({
        where: { id: skuId },
        data: { qty: qtyAfter }
    });
    
    // 4. 更新批號庫存（如有批號）
    if (lotNumber) {
        await tx.inventoryLot.updateMany({
            where: { skuId, lotNumber },
            data: { qty: { increment: qtyChange } }
        });
    }
});
```

## 四、業務單據狀態流轉

### 4.1 領料單（MaterialIssue）

```
┌─────────┐    發料扣帳    ┌─────────┐
│  draft  │ ─────────────→ │ issued  │
│  草稿   │               │  已發料  │
└─────────┘               └─────────┘
     │ 刪除
     ↓
  (移除記錄)
```

**狀態說明：**
- `draft`：草稿狀態，可編輯、可刪除
- `issued`：已發料狀態，觸發庫存扣減

**發料流程：**
```
建立領料單 (draft) 
    ↓
審核領料單
    ↓
[觸發點] POST /api/inventory/issues/:id/issue
    ↓
┌─────────────────────────────────────────┐
│ 1. 檢核欠料數量（不得超領）              │
│ 2. 建立庫存異動：type='領料出庫'        │
│ 3. 更新 SKU 庫存：qty - qtyIssued       │
│ 4. 更新批號庫存：lot.qty - qtyIssued    │
│ 5. 更新領料單明細狀態為 'issued'        │
│ 6. 更新領料單主檔狀態為 'issued'        │
│ 7. 更新工單用料檔 issuedQty/shortageQty │
└─────────────────────────────────────────┘
```

### 4.2 退料單（MaterialReturn）

```
┌─────────┐    退料加帳    ┌──────────┐
│  draft  │ ─────────────→ │ returned │
│  草稿   │               │  已退料   │
└──────────┘              └──────────┘
```

**狀態說明：**
- `draft`：草稿狀態，可編輯
- `returned`：已退料狀態，觸發庫存增加

**退料流程：**
```
建立退料單 (draft)
    ↓
[觸發點] POST /api/inventory/returns/:id/return
    ↓
┌─────────────────────────────────────────┐
│ 1. 建立庫存異動：type='退料入庫'        │
│ 2. 更新 SKU 庫存：qty + qty             │
│ 3. 更新/建立批號庫存                    │
│ 4. 更新退料單狀態為 'returned'          │
└─────────────────────────────────────────┘
```

### 4.3 補料單（MaterialSupplement）

```
┌─────────┐    補料加帳    ┌─────────┐
│  draft  │ ─────────────→ │ issued  │
│  草稿   │               │  已補料  │
└─────────┘               └─────────┘
     │ 取消
     ↓
  cancelled
```

### 4.4 委外加工單（SubcontractOrder）

```
┌─────────┐  發料扣帳  ┌──────────┐  收貨加帳  ┌───────────┐  關閉  ┌────────┐
│  draft  │ ─────────→ │ released │ ─────────→ │ completed │ ─────→ │ closed │
│  草稿   │            │  已發料   │            │   已完成    │       │  已結案 │
└─────────┘            └──────────┘            └───────────┘       └────────┘
                              │
                              │ 再次發料
                              ↓
                        ┌──────────────┐
                        │ in_progress  │
                        │   進行中     │
                        └──────────────┘
```

**狀態說明：**
- `draft`：草稿狀態
- `released`：已發布，首次發料後
- `in_progress`：進行中，多次發料
- `completed`：已完成收貨
- `closed`：已結案

### 4.5 調撥單（TransferOrder）

```
┌─────────┐   審核   ┌──────────┐   出庫扣帳  ┌────────────┐  入庫加帳  ┌───────────┐
│  draft  │ ───────→ │ approved │ ──────────→ │ in_transit │ ────────→ │ completed │
│  草稿   │          │  已審核   │            │   運輸中    │          │   已完成   │
└─────────┘          └──────────┘            └────────────┘          └───────────┘
     │                                                                      ↑
     └─────────────── 取消 ──────────────────────────────────────────────────┘
                                    │
                                    ↓
                              ┌───────────┐
                              │ cancelled │
                              └───────────┘
```

**狀態說明：**
- `draft`：草稿狀態
- `approved`：已審核，可執行出庫
- `in_transit`：運輸中（調撥出庫完成）
- `completed`：已完成（調撥入庫完成）
- `cancelled`：已取消

**調撥流程：**
```
建立調撥單 (draft) → 驗證庫存足夠
    ↓
審核調撥單 (approved)
    ↓
[觸發點1] POST /api/inventory/transfers/:id/pick
    ↓
┌─────────────────────────────────────────┐
│ 調撥出庫：                              │
│ 1. 建立庫存異動：type='調撥出庫'        │
│ 2. 扣減來源倉庫 SKU 庫存                │
│ 3. 更新明細狀態為 'in_transit'          │
│ 4. 更新主檔狀態為 'in_transit'          │
└─────────────────────────────────────────┘
    ↓
[觸發點2] POST /api/inventory/transfers/:id/receive
    ↓
┌─────────────────────────────────────────┐
│ 調撥入庫：                              │
│ 1. 建立庫存異動：type='調撥入庫'        │
│ 2. 增加目標倉庫 SKU 庫存                │
│ 3. 更新/建立目標倉庫批號庫存            │
│ 4. 更新明細狀態為 'received'            │
│ 5. 更新主檔狀態為 'completed'           │
└─────────────────────────────────────────┘
```

### 4.6 完工入庫單（CompletionOrder）

```
┌─────────┐   品檢通過  ┌──────────┐   入庫加帳  ┌───────────┐
│  draft  │ ─────────→ │ approved │ ──────────→ │ completed │
│  草稿   │            │  已核准   │            │   已完成   │
└─────────┘            └──────────┘            └───────────┘
     │                       ↑
     ↓ 品檢                  │
┌────────────┐               │
│ qa_pending │ ──────────────┘
│ 品檢待審   │
└────────────┘
```

**狀態說明：**
- `draft`：草稿狀態
- `qa_pending`：品檢待審核
- `approved`：品檢通過，可執行入庫
- `completed`：已完成入庫
- `cancelled`：已取消

**完工入庫流程：**
```
建立完工入庫單 (draft)
    ↓
品檢審核 (qa_pending → approved/failed)
    ↓
[觸發點] POST /api/inventory/completions/:id/receive
    ↓
┌─────────────────────────────────────────┐
│ 完工入庫：                              │
│ 1. 建立庫存異動：type='完工入庫'        │
│ 2. 增加成品 SKU 庫存                    │
│ 3. 建立/增加批號庫存                    │
│   - 包含製造日期、有效期限              │
│   - 包含儲位資訊                        │
│ 4. 更新工單實際產量 actualQty           │
│ 5. 更新明細狀態為 'received'            │
│ 6. 更新主檔狀態為 'completed'           │
└─────────────────────────────────────────┘
```

## 五、批號與效期管理

### 5.1 批號資料模型

```prisma
model InventoryLot {
  id               String    @id @default(uuid())
  skuId            String    // 關聯品號
  lotNumber        String    // 批號
  qty              Int       @default(0)  // 批號庫存數量
  warehouse        String    // 倉庫
  location         String?   // 儲位
  manufactureDate  DateTime? // 製造日期
  expiryDate       DateTime? // 有效期限
  status           String    @default("active")
  
  @@unique([skuId, lotNumber])  // 同一品號的批號不重複
}
```

### 5.2 批號生命週期

```
入庫時建立批號 → 使用中扣減 → 歸零時標記為 inactive
     ↓
效期管理：
  - 製造日期追蹤
  - 有效期限追蹤
  - 效期預警（critical/warning/notice）
```

### 5.3 批號異動邏輯

**入庫時：**
- 檢查批號是否存在
- 存在：累加數量
- 不存在：建立新批號記錄

**出庫時：**
- 扣減批號數量
- 使用 FIFO（先進先出）或指定批號
- 扣減至 0 時標記為 inactive

### 5.4 效期預警機制

| 預警等級 | 剩餘天數 | 處理方式 |
|---------|---------|---------|
| `critical` | < 7 天 | LINE 推播通知 |
| `warning` | < 30 天 | LINE 推播通知 |
| `notice` | < 90 天 | 系統顯示預警 |

### 7.1 補貨觸發流程

```

  ↓
AutoReplenishment 建立 (含建議訂購量)
  ↓
LINE 低庫存預警通知
  ↓
一鍵建立請購單 (PR)
  ↓
進入採購流程
```

### 7.2 動態 ROP 計算

```
ROP = (平均日需求量 × 前置時間) + 安全存量

其中：
- 平均日需求量 = 近6個月出庫總量 / 180天
- 前置時間 = SKU.leadTimeDays（預設7天）
- 安全存量 = SKU.safetyStock
```

## 九、關鍵技術實作細節

### 9.1 事務處理（Transaction）

所有庫存異動都使用 Prisma 的 `$transaction` 確保資料一致性：
- **原子性**：所有操作要么全部成功，要么全部失敗
- **一致性**：庫存數量與異動紀錄同步更新
- **隔離性**：並發操作不會導致庫存負數

### 9.2 庫存檢核機制

- **領料前**：檢核庫存是否足夠
- **調撥前**：驗證來源倉庫庫存
- **超領檢核**：比對工單用料檔的 `shortageQty`

### 9.3 LINE 推播預警

系統在以下情況自動發送 LINE 通知：
- 效期嚴重預警（< 7 天）
- 效期警告預警（< 30 天）
- 低庫存預警（觸發 ROP）
- 超量庫存預警（超過最高庫存量）
