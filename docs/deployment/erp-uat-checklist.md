# ERP 使用者驗收（UAT）檢核清單

## 目的與範圍

本清單供 HR、人資薪資、倉管、生產現場及其主管執行業務驗收。這是待執行的驗收計畫，不代表 UAT 已完成或任何業務流程已獲簽認。

隔離 UAT Compose 的 Web 入口為 `http://localhost:5176/`、API 健康檢查為 `http://localhost:5102/health`；員工 App 應使用另一個瀏覽器來源（預設 `http://localhost:5177/`）並指向隔離 API。一般本機 Compose 的 `5173`／`5100` 與既有員工 App `5174` 不屬於此隔離環境，不能用來執行會寫入的 UAT。除非已確認使用本文件定義的隔離資料庫，否則只執行唯讀檢查。

### 已知驗收限制

- **請假：** 班表／假日日曆與假額交易尚未完成；目前建立及核准請假會 fail-closed（HTTP 503），且不得寫入或改變申請狀態。可驗證保護行為，但不能簽認請假流程完成。既有 `TEST` 待審申請須保留原狀，交由 HR 決定，不得在 UAT 中自行核准或刪除。
- **薪資：** 目前沒有可供員工查詢的已發放薪資資料，薪資公式及法規參數尚未完成 HR 核定。不得建立虛構薪資、執行薪資計算或將測試資料標記為已發放。
- **打卡：** 曾因位置不在已設定地理圍欄內而遭拒絕。只在公司核准地點，以實際裝置及核准帳號驗證；不得偽造座標或未經核准變更圍欄。
- **庫存與生產：** 只可用核准的測試倉庫、測試料號、隔離工單及可還原資料執行會寫入或過帳的案例。先前確認的領料來源倉為 `FW02`；執行前仍須由倉管確認該測試資料的來源倉與期初量。
- **WIP 與扣庫：** 依目前流程分開驗收：領料過帳扣減原料庫存；WIP 報工核准更新工單／工序進度，不再次扣減同一批原料，以避免重複扣料。若業務要求報工觸發倒扣，須另行核定倒扣時點、BOM 用量、重複提交冪等性及退回／沖銷規則後再改變預期。
- **QR 盤點與 FQC：** 已加入員工 App 與 Web 相機掃描入口，QR 格式為 `料號|批號|YYYY-MM-DD`，日期代表效期。程式建置與單元測試通過後，仍須在隔離 UAT 以合成批號實測相機權限、盤點差異過帳與 FQC 待判定流程；不得視為已完成業務驗收。
- **告警：** 本機 Alertmanager 為 UI/API 輪詢模式，不會寄送 Email、Slack 或 Webhook；不得把本機告警頁面視為正式通知驗收。

### 隔離環境與合成帳號

- 使用 `deployment/docker-compose.uat.yml`，並以獨立 Compose project `erp-uat` 啟動；資料庫 volume 為該 project 專屬，不掛載或複製一般 Compose 的 `postgres_data`。
- Compose 僅將 API `5102`、Web `5176` 綁定 loopback；PostgreSQL 不發布到主機連接埠。不得改成 `0.0.0.0` 或連到正式資料庫。
- `deployment/.env.uat.local` 僅存放本機隨機 UAT 密鑰與初始管理員密碼，已由 `.gitignore` 排除；不可提交、貼到聊天或複製至正式環境。
- 建議使用不含個資的合成帳號：`uat-admin`（只供管理測試設定）、`uat-employee`、`uat-hr`（HR Manager）、`uat-warehouse-operator`／`uat-warehouse-approver`（依最小權限建立隔離測試角色）、`uat-production-operator`（Operator）、`uat-production-supervisor`（Production Supervisor）。所有密碼由系統在本機產生／設定，不共用正式帳密。
- HR 員工、料號／批號、倉庫／儲位、BOM、工單與期初量均須使用標記明確的合成資料。執行前由隔離資料庫確認初始化與資料識別碼；不得把共用資料庫中的個人或業務資料搬入 UAT。
- 員工 App 的 `EXPO_PUBLIC_API_BASE_URL` 必須指向 `http://localhost:5102/api/erp`。UAT App 使用 `5177`，避免重用既有 `5174` 網頁來源的登入狀態。

### 本機隔離環境操作

以下命令使用本機 `.env.uat.local` 密鑰；不要在終端輸出或分享該檔內容。

```powershell
# 建立一次性本機密鑰檔（不提交），每個值均使用隨機值
# 啟動／查詢僅限 UAT project 的服務
docker compose --env-file deployment/.env.uat.local -p erp-uat -f deployment/docker-compose.uat.yml up -d --build
docker compose --env-file deployment/.env.uat.local -p erp-uat -f deployment/docker-compose.uat.yml ps
```

移除 UAT 資料時，須先確認目前 Compose project 明確為 `erp-uat`，再由負責人核准移除該 project 專屬 volume；不得對一般 `deployment/docker-compose.yml` 執行 `down -v`。

## 執行前檢查

- [ ] 業務負責人確認本次執行的是本機／測試環境，而非正式環境。
- [ ] DBA／系統管理員確認資料庫已隔離、已備份，且有明確的資料清理或還原方式。
- [ ] 各部門提供具名測試帳號；每個帳號只具備該角色所需權限，不共用管理者帳號。
- [ ] 準備合成且不含個資的測試員工、測試料號、測試倉庫、測試工單及唯一 UAT 標記。
- [ ] 執行前記錄測試資料識別碼與關鍵期初值；不得將密碼、Token、薪資或個資放入截圖與驗收紀錄。
- [ ] 確認測試人員知道遇到未預期的過帳、重複扣料或跨員工資料時，應立即停止並通知系統管理員。

## 驗收案例

### UAT-01：登入、角色與登出

**負責人：** 各部門測試代表、系統管理員

- [ ] 以核准帳號登入，確認顯示的使用者與所屬角色正確。
- [ ] 確認使用者只看到該角色授權的模組與資料。
- [ ] 登出後重新整理頁面或直接開啟受保護頁面，確認不會沿用已登出的工作階段。
- [ ] 以無權限帳號嘗試開啟受限制功能，確認被拒絕，且沒有資料變更。

**通過條件：** 登入身分、角色權限及登出狀態正確；不得以隱藏按鈕代替伺服器端授權檢查。

### UAT-02：領料過帳與庫存數量（僅限隔離測試資料）

**負責人：** 倉管、庫存管理者

- [ ] 確認測試領料單、測試料號、單位及來源倉；若使用先前確認的來源倉，須確認為 `FW02` 的測試資料。
- [ ] 記錄過帳前該料號、倉庫／儲位的可用量及保留量。
- [ ] 建立測試領料單並過帳一次；確認單據狀態、來源倉、數量與操作者正確。
- [ ] 重新整理並重新查詢「庫存管理中心 → 異動明細」及庫存結餘；確認異動已記錄且來源倉數量按過帳量減少。
- [ ] 再次重新整理，不重複送出；確認沒有重複扣庫。
- [ ] 使用超過可用量或無效數量的測試案例（僅在安全隔離資料中），確認系統拒絕且庫存及異動紀錄不變。

**通過條件：** 單據、異動明細及庫存結餘一致；只扣帳一次；異常操作不留下部分更新。若無隔離資料或無法確認倉庫，不執行過帳。

### UAT-03：庫存盤點與調整（僅限隔離測試資料）

**負責人：** 倉管、庫存主管

- [ ] 使用 `料號|批號|YYYY-MM-DD` QR 掃描或手動輸入，確認料號、批號與效期正確。
- [ ] 選擇核准的測試倉庫，讀取該料號／批號帳面數，輸入實盤數並核對差異。
- [ ] 尚未明確確認前，重新查詢庫存，確認數量與異動明細不變。
- [ ] 由具 `inventory:execute` 權限的測試人員明確確認一次，確認差異過帳、效期更新且異動可追溯。
- [ ] 使用舊帳面數重送過帳，確認伺服器拒絕過期盤點資料；確認刷新帳面數後才可重新盤點。
- [ ] 以無盤點執行權限帳號嘗試過帳，確認操作被拒絕且資料不變。

**通過條件：** 料號、倉庫、批號及效期正確；過帳前數量不變；明確確認後的差異、異動及結餘一致；舊帳面數與無權限操作均被拒絕。此 MVP 由具執行權的盤點人員明確確認即過帳，未包含獨立主管核准步驟。若無隔離測試資料，記錄為「未執行／阻塞」，不可改用正式庫存。

### UAT-04：領料、BOM 用量與生產工序報工（僅限隔離測試資料）

**負責人：** 生產操作員、生產主管

- [ ] 確認測試工單已核准、工序及前序良品量正確，且不會影響正式排程或成本。
- [ ] 依工單 BOM 建立並過帳測試領料單；核對原料倉庫結餘與異動明細各減少一次，確認耗用量及單位符合核准 BOM。
- [ ] 以操作員帳號填報測試工序、時間、良品／不良／報廢數量；最後工序需依系統要求填寫成品批號。
- [ ] 提交後確認報工為待審狀態，且核准前未計入正式生產進度。
- [ ] 驗證報工數不大於前序可報量；驗證結束時間晚於開始時間，單筆時段不超過 24 小時。
- [ ] 以主管帳號核准一次，確認工單進度與報工單更新一致；另以一般操作員帳號驗證無權核准。
- [ ] WIP 核准後再次查核原料庫存，確認沒有因報工重複扣料；另依核准報廢容差驗證超量報廢防呆。
- [ ] 驗證退回時需提供原因，並確認退回報工可依既定流程修正與重新送審。

**通過條件：** 領料單、原料異動及結餘一致；報工待審／核准狀態、工序進度及批號一致；報工不造成第二次原料扣帳；限制與審核權限生效。

### UAT-08：QR 盤點與成品 FQC（僅限隔離測試資料）

**負責人：** 倉管、品保、生產主管、系統管理員

- [ ] 於員工 App 與 Web 分別允許相機權限，以隔離測試 QR 掃描 `料號|批號|YYYY-MM-DD`；確認日期以效期顯示。
- [ ] 掃描錯誤日期、缺欄或額外欄位的 QR，確認解析失敗且沒有資料寫入。
- [ ] 以合成測試批號選擇料號相符、已完成末工序報工的工單，輸入抽樣數、不良數及檢驗人員後建立 FQC。
- [ ] 確認 FQC 批號與效期被保存，狀態為「待判定」；掃描本身不得自動判定合格或放行。
- [ ] 以不匹配料號的工單及沒有末工序報工的批號測試，確認後端拒絕建立 FQC。
- [ ] 依既有 FQC 權限流程另行人工判定，確認待判定 FQC 可在 Web 查閱；本案例不得略過品質判定。

**通過條件：** App 與 Web 相機皆能解碼且格式驗證一致；效期與批號正確持久化；錯誤資料不落庫；FQC 保持待判定且不因掃描自動合格。只在隔離工單及可還原資料上執行。
### UAT-05：公司現場打卡

**負責人：** HR、員工代表、系統管理員

- [ ] HR 先確認核准的地理圍欄、班別、打卡政策及測試員工。
- [ ] 員工在核准地點以實際手機／瀏覽器完成一次測試打卡，記錄裝置、時間及結果。
- [ ] HR 核對出勤紀錄、伺服器時間、員工及班別。
- [ ] 不要求員工到圍欄外測試真實打卡，也不修改裝置位置；若需驗證拒絕情境，使用已核准的自動化測試或隔離測試帳號。

**通過條件：** 實際地點與核准政策相符，紀錄可由 HR 查核；若位置遭拒絕，保留錯誤訊息供管理者檢查，不得擴大圍欄以求通過。

### UAT-06：請假保護行為（目前只驗證 fail-closed）

**負責人：** HR、系統管理員

- [ ] 使用隔離測試帳號嘗試提交測試請假，確認目前系統回傳 503／明確不可用訊息。
- [ ] 查詢資料庫或由授權管理者核對，確認沒有新增申請、假額扣抵或部分更新。
- [ ] 若測試有既存待審申請，確認狀態未被意外改變；不得核准或刪除該資料。
- [ ] 紀錄此案例為「保護行為通過；請假業務流程尚未驗收」，並指派班表／假日日曆、假額規則及交易完整性的後續負責人。

**通過條件：** 不完整的政策／交易能力下，系統拒絕寫入且資料不變。此結果不能作為請假流程可上線的簽核。

### UAT-07：員工薪資明細與資料隔離

**負責人：** HR 薪資管理者、員工代表、系統管理員

- [ ] 使用測試員工帳號確認目前無已發放測試薪資時，畫面明確顯示無資料，不出現其他員工薪資。
- [ ] 若日後已取得核准且隔離的測試薪資資料，再驗證本人可讀取已發放明細、金額與期間正確。
- [ ] 嘗試存取另一名員工的測試明細，確認伺服器端拒絕且不洩露資料。
- [ ] 不執行薪資計算、不建立假薪資、不變更正式薪資狀態；公式與法規參數需先由 HR 核定。

**通過條件：** 本人資料範圍及空資料狀態正確；未授權跨員工存取遭拒。薪資計算與薪資內容若未核定，標記為未驗收。
