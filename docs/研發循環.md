在模組化 ERP 的「研發循環」（R&D Cycle）中，核心目標是將市場需求轉化為可量產的產品規範，並確保技術資產（Intellectual Property）的完整性與安全性。

以下為產品設計開發、技術研發記錄及文件保管系統 (DMS) 的詳細表單欄位規劃：

### 1. 研發專案/產品開發計畫書 (R&D Project Plan)

這是研發起點，定義專案目標與資源投入。

* **專案基本資訊**：專案編號、專案名稱、專案經理 (PM)、專案類別（新產品/規格改良/技術研究）。
* **市場需求維度**：對應客戶代碼（若是客製化研發）、市場調查單號、預計目標單價。
* **開發時程**：預計啟動日、預計樣品完成日、預計投產日、各階段里程碑 (Milestones)。
* **預算預估**：預計研發經費、人力成本預估（連動預算規劃循環）。
* **風險評估**：技術可行性、法規合規性（如：UL, CE, RoHS）。

### 2. 產品規格書/技術需求表 (Product Specification)

記錄產品的物理與功能屬性。

* **產品識別**：暫定品號、品名、產品系列。
* **技術參數**：尺寸公差、材質要求、環境適應性（溫度/濕度）、性能指標（如：輸出功率、抗壓值）。
* **包裝規範**：包裝方式、標籤要求、物流限制。
* **認證要求**：應符合之國際標準或產業規範清單。

### 3. 技術研發紀錄/實驗日誌 (R&D Log & Experiment Report)

記錄開發過程中的技術細節與實驗數據，是專利申請的重要依據。

* **紀錄資訊**：實驗單號、紀錄人員、日期、實驗地點。
* **實驗參數**：測試條件（電壓、轉速、壓力等）、對照組資訊。
* **數據回饋**：實測結果值、數據圖表附件、失敗原因分析。
* **結論與建議**：是否通過測試、後續改良方向。
* **知識庫標記**：技術關鍵關鍵字（用於日後檢索）、機密等級設定。

### 4. 工程變更通知/申請單 (ECN / ECR)

當產品量產後或開發中需修改設計時的控管表單。

* **變更類別**：規格修正、物料替代、製程優化、成本降低。
* **影響範圍**：受影響的品號、BOM 版本、現有庫存處理建議（報廢/改修/用到完）。
* **變更對照**：變更前規格/圖面 vs. 變更後規格/圖面。
* **生效日期**：強制執行日或批次切換日。
* **會簽部門**：生管（核對庫存）、採購（聯絡供應商）、品保（重新驗證）。

### 5. 文件保管系統 (DMS) 索引與權限表

管理研發圖紙、軟體原始碼與技術文件。

* **文件元數據**：文件編號、文件名稱、版本號 (Revision)、文件類型（CAD圖紙、PDF說明書、原始碼）。
* **生命週期管理**：草稿、審核中、已發行、已作廢。
* **存取權限控管**：
* **角色權限**：僅閱覽、可下載、可修改、可列印（浮水印浮現）。
* **安全屬性**：是否加密、解密申請單號、文件有效期限。


* **關聯性標籤**：關聯產品編號、關聯 ECN 單號、專案代碼。

### 6. 樣品領料/試產單 (Sample Request / Pilot Run)

研發轉量產前的實體驗證。

* **需求資訊**：樣品用途（測試/參展/送客）、需求數量。
* **物料來源**：倉庫撥發、採購急件、手工製作零件。
* **試產紀錄**：試產良率、組裝難易度回饋（DFM - Design for Manufacturing）、工時實測。

---

### 系統設計邏輯建議：

1. **PLM 與 ERP 的橋接**：研發完成後，系統應具備「一鍵轉正」功能，將研發 BOM 自動發布為生產 BOM (Production BOM)，避免人工重複輸入出錯。
2. **電子簽章與時戳 (Digital Signing)**：研發紀錄應強制掛載電子簽章與不可篡改的時戳，以在智慧財產權訴訟中具備法律效力。
3. **版本自動追蹤**：DMS 應具備版本比對功能，當設計圖更換時，系統需自動警示所有關聯的採購單與生產單。
4. **跨模組成本連動**：研發階段填寫的「預估單價」應與採購模組的「詢價紀錄」自動比對，若實際採購成本遠超預算，系統需向 PM 發出預警。
